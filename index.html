7 · Theory

7.1 What is cache memory?

Cache memory is a small, very fast memory placed between the CPU and main memory (RAM). It holds copies of the main-memory blocks that the CPU is likely to need again soon. When the CPU requests data, the request is first sent to the cache. If the data is present we have a HIT and main memory is not touched; if it is absent we have a MISS and the whole block containing the data is fetched from main memory into the cache. Cache memory is required because of the large speed gap between fast CPUs and slower main memory: without a cache the CPU would spend most of its time waiting for memory.

7.2 Blocks, lines and tags

  • Main memory and cache are divided into fixed-size chunks called blocks (main memory) or lines/frames (cache).
  • Block size = line size. Number of memory blocks = Memory size / Block size and Number of cache lines = Cache size / Block size.
  • When a block is copied into the cache, the cache stores a tag — extra bits that record which memory block the line currently holds.
  • On every access the hardware compares the tag of the requested block with the tags of the relevant line(s) to decide HIT or MISS.

7.3 Direct mapping

Each memory block has exactly one possible cache line. The line number is computed from the block number:

Cache line = Block number mod Number of cache lines     Tag = floor(Block number / Number of cache lines)

The block number is split as [ Tag | Line number | Block offset ], so the hardware needs no search — it goes straight to the single line.

Worked example: Memory = 512 B, cache = 128 B, block = 16 B ⇒ 32 blocks, 8 cache lines. Block 13: line = 13 mod 8 = 5, tag = floor(13 / 8) = 1. Block 13 can live only in line 5.

Advantages: simplest and cheapest hardware; very fast (no search). Disadvantages: two blocks that map to the same line keep evicting each other (conflict misses), even if other lines sit empty.

7.4 Fully associative mapping

Any block can be placed in any cache line. There is no line field at all:

Tag = Block number (the whole block number is stored as the tag)

On every access the tag is compared with all lines in parallel. If the block is absent, an empty line is used, or a victim is chosen by a replacement policy (FIFO / LRU).

Worked example: 8 cache lines. Block 13 ⇒ tag = 13; the block may be loaded into any of lines 0–7, e.g. line 2 if it is empty.

Advantages: no conflict misses; highest possible hit ratio. Disadvantages: needs one comparator per line (expensive) and a replacement algorithm; slower and costlier than direct mapping.

7.5 Set-associative mapping

A compromise: the cache lines are grouped into sets, and each block maps to exactly one set — but it may occupy any line (way) inside that set.

Number of sets = Number of cache lines / Associativity     Set = Block number mod Number of sets     Tag = floor(Block number / Number of sets)

Worked example: 8 cache lines, 2-way ⇒ 4 sets. Block 13: set = 13 mod 4 = 1, tag = floor(13 / 4) = 3; block 13 may be placed in either way of set 1 (lines 2 or 3).

Advantages: removes most conflict misses while keeping hardware cost reasonable; the most widely used scheme in real processors (e.g. 4-way, 8-way, 16-way caches). Disadvantages: still needs comparators and a replacement policy per set; slightly slower than direct mapping.

7.7 Replacement policies (FIFO and LRU)

  • FIFO (First In, First Out): evict the block that was loaded earliest, regardless of use. Simple, but may evict a frequently used block just because it is old.
  • LRU (Least Recently Used): evict the block that has not been used for the longest time. Follows the principle of locality, so it usually gives a better hit ratio than FIFO, at the cost of tracking usage.

Worked difference (2-line cache, sequence 0, 1, 0, 2, 1): FIFO gives HIT at step 5; LRU gives a MISS at step 5 because LRU evicted block 1 at step 4.

7.8 Hit ratio and miss ratio

Hit ratio = Hits / Total accesses × 100%     Miss ratio = Misses / Total accesses × 100%     (Hit ratio + Miss ratio = 100%)

A higher hit ratio means the CPU is served by fast cache memory more often, so the average memory-access time is lower: Average access time = Hit time + Miss ratio × Miss penalty.
